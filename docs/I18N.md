# Preferred language (i18n foundation)

## Shipped

- `User.preferredLocale` (BCP-47, default `en-GB`) — Prisma + Netlify SQL migration
- Settings → Appearance control — **broad preference list** (`LOCALE_IDS` / `SUPPORTED_LOCALES` in `lib/i18n.ts`): major world languages plus common football markets (AR, NL, PL, SV, NO, DA, FI, JA, KO, ZH, HI, ID, MS, TH, VI, UK, RU, EL, CS, RO, HU, HR, SR, SK, BG, HE, FA, SW, …). Labels via `Intl.DisplayNames`. Searchable picker when the list is long.
- `normalizeLocale` accepts any listed id; unknown → `en-GB`. Language-only tags map to a sensible regional default (e.g. `en` → `en-GB`).
- `PATCH /api/auth/me` `{ preferredLocale }` + `GET` returns it
- `LocaleProvider` / `useLocale()` — localStorage cache + account sync
- High-visibility strings: header “Commentary desk”, feed sync / linked labels (partial `STRINGS`; missing locales fall back to en-GB)

## Language requests

- Settings → Appearance includes **Request a new language** (name + optional note).
- `POST /api/language-request` appends to `data/language-requests.jsonl` (same local stub pattern as feedback; inbox / DB later). Confirmation shown in UI.

## Current gap

**Preference list is broad; full UI translation is the remaining gap.** Most chrome still renders English until the `STRINGS` catalogue grows. Saving a non-English locale is supported and persisted; `t()` falls back to en-GB for keys without a translation.
